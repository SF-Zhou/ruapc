01 Why RuaPC

The transport is a detail.
Your service isn't.

Start on TCP. Add WebSocket, HTTP, or RDMA when the deployment asks for it. The service definition, typed calls, deadlines and failure model stay put.

A / Codegen

Typed end to end.

#[ruapc::service] generates typed client methods, server dispatch and OpenAPI schemas. Invalid signatures fail at the source span, not at runtime.

B / Reverse RPC

Calls can go back.

Persistent transports let a handler call into the client. No side channel, no second control API, no special case in the service definition.

C / Endpoints

One endpoint contract.

A scheme plus one or more equivalent addresses. Transport pools own connection caching, coalescing and address fallback.

02 The API

From trait to traffic
in three moves.

The macro does the glue. You keep ordinary async Rust: a trait, an implementation, and a call.

src/service.rs 
use ruapc::{Context, Result};
use schemars::JsonSchema;
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, JsonSchema)]
pub struct Request(pub String);

#[ruapc::service]
pub trait EchoService {
    async fn echo(&self, ctx: &Context, req: &Request) -> Result<String>;
}

struct Echo;

impl EchoService for Echo {
    async fn echo(&self, _ctx: &Context, req: &Request) -> Result<String> {
        Ok(req.0.clone())
    }
}
use std::sync::Arc;
use ruapc::{ListenMode, Router, Server, SocketPoolConfig};

#[tokio::main]
async fn main() -> std::result::Result<(), Box<dyn std::error::Error>> {
    let config = SocketPoolConfig {
        listen_mode: ListenMode::UNIFIED,
        ..Default::default()
    };

    let mut router = Router::default();
    EchoService::ruapc_export(Arc::new(Echo), &mut router);

    let server = Server::create(router, &config)?;
    server.listen("0.0.0.0:8000".parse()?).await?;

    tokio::signal::ctrl_c().await?;
    server.stop();
    server.join().await;
    Ok(())
}
use ruapc::{Client, Context, SocketPoolConfig};

#[tokio::main]
async fn main() -> std::result::Result<(), Box<dyn std::error::Error>> {
    let config = SocketPoolConfig::default();
    let ctx = Context::create(&config)?
        // tcp:// → ws:// → http:// → http+rdma://
        .with_endpoint("ws://127.0.0.1:8000".parse()?);

    let response = Client::default()
        .echo(&ctx, &Request("Rua!".into()))
        .await?;

    assert_eq!(response, "Rua!");
    Ok(())
}

03 The wires

Pick a wire.
Keep the code.

Every transport is a typed endpoint. Persistent transports add reverse RPC; RDMA adds kernel bypass and READ-based transfers. A unified listener can speak TCP, WebSocket and HTTP on the same port.

01

TCP

Persistent streams with reverse RPC and inline remote memory. The zero-ceremony default.

tcp://host:8000
  • persistent
  • reverse RPC
  • inline memory

no RDMA toolchain

02

WebSocket

The same persistent contract over an HTTP upgrade, using WebSocket framing.

ws://host:8000
  • persistent
  • HTTP upgrade
  • reverse RPC

shares the unified port

03

HTTP/2

Typed streams for reverse RPC and remote memory, plus plain JSON POST for ordinary callers.

http://host:8000
  • h2 streams
  • JSON POST
  • RapiDoc

docs ship at /rapidoc

04

RDMA

Optional kernel-bypass transport with READ-based transfers. Bootstraps over TCP, WebSocket, HTTP or a unified listener.

tcp+rdma://host:8000
  • optional
  • kernel bypass
  • RDMA READ

feature = "rdma"

Unified listener

One port accepts TCP, WebSocket and HTTP. With RDMA enabled, the same listener carries bootstrap.

ListenMode::UNIFIED

Typed HTTP/2 streams support reverse RPC and remote memory. Ordinary unary HTTP POST calls are JSON and unary. Read the transport contracts

04 Remote memory

Move bytes.
Keep ownership.

Attach owned buffers to a call and address them as one flat CopyOp space. RuaPC fragments the ranges, validates bounds and overlap, and picks the path: RDMA READ or inline reverse RPC.

  • Owned read sources and exclusive write destinations.
  • Read-then-validate results; recoverable failures return buffers when the contract allows.
  • Works over TCP, WebSocket, typed HTTP/2 and RDMA.

05 The toolkit

Batteries,
not boilerplate.

The pieces you would otherwise wire together ship with the library: schemas, docs, codecs, deadlines and metrics.

01

Codegen, not boilerplate.

Define one trait. Get a typed client, server dispatch and an OpenAPI schema. Reserved names and bad signatures fail at compile time.

#[ruapc::service]
02

Docs at the endpoint.

RapiDoc at /rapidoc; the schema at /openapi.json. Documentation moves with the service, not a separate deployment.

/openapi.json
03

MessagePack or JSON.

MessagePack payloads by default; JSON when a caller asks. Unary HTTP endpoints accept JSON directly.

rmp-serde · serde_json
04

Deadlines that travel.

Context deadlines propagate to transports. Nested calls are capped by the parent's remaining budget.

ctx.deadline()
05

Bring your own metrics.

Emit through the metrics facade. Per-method handles are cached per state; accounting settles on completion, cancellation or panic.

metrics facade
06

Safe at the core.

ruapc forbids unsafe. Allocation, registration and verbs sit behind owned-safe APIs in ruapc-bufpool and ruapc-rdma.

#![forbid(unsafe_code)]
07

Endpoint groups.

One endpoint can name a sorted, deduplicated group of equivalent addresses. Pools cache by the complete group and handle fallback without merging overlapping sets.

tcp://a:8000,b:8000
